SYSTEM MAP

Follow the disk.

A VM leaves Nutanix as a plain qcow2 plus a manifest. Everything after that is standard Linux virtualization.

WHO DOES WHAT

Each project does one job.

Transiva

Discover and export

Talks to Prism Central v4, finds the VM and its disks, picks the disk up from the NFS storage container, converts it with qemu-img and writes artifact-manifest.json. The source VM is never modified.

h2kvm

Repair and convert

Takes the disk and makes it boot on KVM: offline guest repair through GuestKit, conversion, checksum and a domain definition. Windows, UEFI, multi-disk and large VMs are h2kvm's territory.

Zorvia

Runs it on KubeVirt

The control plane for KubeVirt. In the run, the migrated VM was Ready and Zorvia listed it as Running through its API.

Kairon

Runs it via Veyron

h2kvm has a Kairon hand-off (--deploy-kairon). It was not run in this test.

Machina

Runs it on libvirt hosts

h2kvm can emit a libvirt domain for a Machina host. A plain libvirt boot was run; Machina itself was not.

Chimera

The test rig

Simulates Nutanix Prism v4 and its NFS container, so the whole path can be tested unattended. It is a simulator, not a real cluster.

STRAIGHT TALK

What this does and doesn't prove.

Proven

  • Prism v4 export in code, end to end
  • Valid qcow2 and manifest, converted by h2kvm
  • Boots on KVM and on KubeVirt, unattended

Not yet

  • A real Nutanix cluster (Prism here is a simulator)
  • Kairon and Machina landings
  • h2kvm guest repair: skipped on the test image
  • Windows, UEFI, multi-disk, large VMs; checks beyond ping
